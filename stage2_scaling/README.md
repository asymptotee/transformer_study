# 阶段二：数据规模如何把"记忆"变成"泛化"

## 要回答的问题

阶段一留下一个悬念：complete（续写）任务靠 300 行真诗只能**背诵**、不能泛化。
那么——

> **如果续写的训练数据大到超过参数容量、背不动了，会是什么结果？**

理论预测（见 `../CONCEPTS.md` 第四、五节）：模型被迫去**压缩**数据，而压缩
自然语言就是学习它的统计结构。于是它从"背下每一句"变成"学会这类句子怎么写"，
开始能续写**没见过的**句子。这正是真实大语言模型的诞生机制。

本阶段用一个可控实验验证这件事：**同一个模型、同一个任务、同样的训练流程，
唯一变量是训练数据量**，看泛化能力如何随之改变。

## 实验设计

### 为什么用合成语料

真实诗句太少（几百行），且没有干净、可泛化的结构，无法做"数据量"的对照实验。
所以用程序生成"伪诗"，它满足三个要求：

1. **有可学结构**——这样泛化才可能发生；
2. **组合空间远大于训练量**——几千行背不完，且验证集能取到真·未见组合；
3. **结构不太简单**——这样小数据才有可能走"背诵"捷径，对比才鲜明。

### 伪诗的"语法"

每行 8 字 = 前 4 字（前景）+ 后 4 字（后情），整行属于同一主题（山/水/花/月/风/云）。
后情字由前景字按两条规则推出：

```
(a) 镜像：后情第 i 字 对应 前景第 3-i 字（位置倒序，像 reverse 的反对角线）
(b) 对仗：每个前景字有固定对仗字（山↔高、峰↔峻、岭↔巍……）

例：前景 山峰岭崖 → 后情 崇巍峻高
    （崖→崇、岭→巍、峰→峻、山→高，倒序 + 替换）
```

模型必须同时发现"反对角线对齐"和"字符对仗表"才能续对。

**组合空间**：6 主题 × 8⁴ = **24576 种前景**，远大于 8000 行训练量。
所以训练集只覆盖一小部分前景，验证集可以取到大量**从没见过的前景**——
在没见过的前景上续对，才算真泛化（`gen_corpus.py` 里严格按"未见前景"过滤验证集）。

### 对照设置

| | 小数据 | 大数据 |
|---|---|---|
| 训练行数 | 300 | 8000 |
| 模型 | 完全相同（d_model=96, 2 层, 约 38 万参数，复用阶段一 `model.py`） |
| 任务 | 完全相同（complete 续写） |
| 训练流程 | 完全相同（AdamW, lr=1e-3） |
| 验证集 | 同一份 600 行"未见前景" |

**指标**：
- `val_loss`：验证集交叉熵（teacher forcing），越低 = 对陌生句子预测越准。
- `exact_acc`：自回归续写验证集，后 4 字**完全续对**的比例。

## 真实结果

```
                   最终 train_loss     最终 val_loss   exact_acc
小数据(300行)              0.0493          0.1311       0.838
大数据(8000行)             0.0068          0.0002       1.000
```

**核心观察：数据量是唯一变量，大数据的泛化质量碾压小数据。**

- **val_loss 相差约 650 倍**（0.1311 → 0.0002）。这是对陌生句子的预测"准头"，
  大数据模型把续写的每一个字都预测得极有把握。
- **exact_acc 从 0.838 → 1.000**：大数据模型在没见过的前景上几乎句句续对，
  小数据模型则有约 16% 续错。
- 大数据模型的 `train_loss ≈ val_loss ≈ 0`（训练/验证都好，无过拟合）；
  小数据模型 `train_loss`(0.049) 明显低于 `val_loss`(0.131)——训练集背得比验证集好，
  露出一点"记忆"的痕迹。

曲线见 `loss_curves.png`（左：val_loss，右：exact_acc）。

## 一个诚实的"意外"，以及它为什么更重要

原本预期小数据会像阶段一 reverse 那样"验证集几乎全错"（exact_acc≈0），
**但实测小数据也摸到了规律（exact_acc 0.838）**。为什么这次没出现灾难性的背诵？

关键在于**数据是否"值得背"**：

- **阶段一 reverse 用 300 行真诗**：每首诗都是有意义、各不相同的内容，模型"背下
  每一首"是有油水的捷径，于是它背了，验证集（陌生诗）全错。
- **本阶段用合成伪诗**：每一行都只是同一规则的随机实例，行与行之间没有可单独
  利用的"内容"。背下 300 个随机实例，不如直接学会那条生成它们的规则划算——
  所以**哪怕只有 300 行，模型也倾向于学规则**，于是也能泛化（只是不如大数据稳、准）。

这反而揭示了一个更深的道理：

> **"背诵"只有在数据 heterogeneous（每条都有可单独记忆的独立内容）时才会成为
> 占优捷径。当数据是同一规律的纯净实例时，规律本身就是最容易的压缩，连小数据
> 都会去学它。数据规模的作用，在这种情况下体现为"学得更稳、更准、更自信"
> （val_loss 650 倍之差），而非"会不会"的二元翻转。**

真实语言介于两者之间：既有可学的统计结构（语法、语义），又有海量"值得记"的事实
（知识、固定搭配）。所以大模型同时在做两件事——学结构 + 记事实——而数据规模
决定了这两者各能做到多好。

## 和大模型的联系

把这里的"大数据模型"放大万亿倍，就是你今天用的每一个 LLM：

- 训练文本远超参数能记的量 → 大部分容量被迫用来**压缩语言的统计结构**（语法、
  语义、推理模式）→ 涌现出对**从未见过的输入**的处理能力。
- "预测下一个 token"（= complete）这个简单目标，在足够大的数据下，逼出了看起来
  像"理解"的能力。

这和阶段一"加 4000 条随机串逼 reverse 学算法"是**同一个原理**，只是规模差了
十个数量级。你不需要教模型"理解"，你只需要给它多到背不完的文本，让它为了压缩
而自己去发现结构。

## 运行


## 局限与可改进

- 伪诗的"语法"是人为设计的干净规则，真实语言的结构更模糊、更统计化。
- 小数据没有灾难性失败（见上文"意外"），若想复现阶段一那种"背诵/全错"的鲜明
  对比，需要让数据 heterogeneous（混入各有独立内容、值得单独记忆的句子）。
- 模型很小（38 万参数）、语料是字符级；真实 LLM 用 BPE 分词、数十亿参数。
  但"数据规模 → 泛化质量"的趋势是一致的。
