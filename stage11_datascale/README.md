# stage11_datascale —— 11.1 数据对齐:官方语料能买多少能力

承接 9.5 桥接的归因("检索之坎的主闸门是数据量")——把归因从"观察官方模型"
变成"自家受控实验":**同架构、同 10000 步、同 seed、同优化配方,只换预训练
语料**(自家 wiki 150MB → minimind 官方 pretrain_t2t_mini),看同一套 20 题
从 0 破不破冰。

## 实验设置

| | 94_full(stage9 基座) | 11-mm(本实验) |
|---|---|---|
| 语料 | 自家 150MB wiki 散文(18,421 篇) | 官方 `pretrain_t2t_mini`(127 万行指令式问答文本) |
| BPE 词表 | 15,124(在 wiki 上训练) | **19,171(在官方语料上重训)** |
| token 量 | 4,390 万 | **3.015 亿(6.9×)** |
| 结构 | 现代全配 117.8M | 同一结构 120.9M(词表变大 +3.1M) |
| 训练 | 10000 步,seed 42 | 完全相同配方(编码缓存 78 min + 训练 93 min) |

**为什么要换词表**:分词器是数据的压缩器,域外文本会被切碎;词表跟数据走
才是正确做法(代价:跨词表 val loss 刻度不可比——见下,可比性全部转移到
20 题 + 固定裁判)。

## 结果

### 语料内:拟合得很好
- 11-mm 语料内 val **2.267(ppl 9.7)**——注意:与 wiki 系数字(3.776)不直接比,
  词表与语料都换了,loss 刻度不同(要公平得按 BPB)

### 20 题:从 0 破冰(核心结果)

| | 94_full(旧语料) | 11-mm(官方语料) | 官方 minimind-3 64M(9.5 测) |
|---|---|---|---|
| 格式 | raw | raw | chat(它的母语) |
| 真实答对 | **0/20** | **ask ≈4/20、fill ≈1/20** | ≈5/20 |

行级审计(ask 6 个关键词命中,4 真 2 假):
- ✓ 故宫位于哪座城市 → "故宫位于**北京市**海淀区…"(城市答对,套话混杂)
- ✓ 世界上最高的山峰是 → "**珠穆朗玛峰**,位于喜马拉雅山脉的尼泊尔和中国的边境线上"(完整正确)
- ✓ 水的化学式是什么 → "**H2O**…"(低频题!)
- (漏判)珠穆朗玛峰的海拔 → "**8,848米**"(内容对,逗号致关键词未匹配)
- ✗ 秦始皇…朝代 → 复读假阳("秦"来自"秦始皇帝")
- 首都题仍崩("中国首都是中国")——"哪里?"式问句壳在该语料占比低,**模板只半覆盖**

**解读**:官方 t2t 语料本身含"故宫位于…""…是珠穆朗玛峰"式陈述 → raw 的
fill/陈述句式部分落进分布 → 破冰;而"问句壳"覆盖不足 → 首都题照旧。
与官方 64M 的"chat 全覆盖 5/20"**不能直接比大小**——两边都是"格式与语料
部分/完全对齐"的产物。同格式严格对比需 10.3(chat-template SFT),诚实开口。

### 迁移探针(wiki 文本 × 新 BPE 重编码,修正版)
- 11-mm 在 wiki 域:**4.690(ppl 108.9)** vs 语料内 2.267——换域代价 ≈ +2.4
  loss:模型"忘了 wiki 腔"(百科长文续写退化,陌生 prompt 现复读:数学是→"数学…
  数学"、鲁迅是→"世界上最大的动物")
- 但通用事实仍存活:"北京是→中国的首都,位于北京"(跨域高频事实留在参数里)
- 诚实边界:该落差混着"域内容差"与"新词表切 wiki 文本的低效",纯域差需
  wiki×新BPE 对照臂(未训,开口记录);94_full 的 3.776 是旧词表刻度,仅供量级

## 结论

1. **9.5 归因在自家受控实验闭环**:同架构同算力,数据 150MB→3 亿 token(6.9×)
   → 20 题 0 → ~4-5/20。数据是闸门,不是参数规模(stage8 归因二的修正,双证据)
2. **格式即分布的教训在更大语料上同样成立**:语料大也没自动学会"问句壳"——
   破冰来自"陈述句模板的半覆盖",不是模板泛化。想要稳定问答 → chat-template
   SFT(10.3)是下一步的自然实验
3. **换域有代价**:目标域拟合好(ppl 9.7),旧域付出 +2.4 loss;通用高频事实
   存活。真实世界"换语料"要掂量保留旧能力的需求
4. **epoch 视角**:同 10000 步,新语料只看 0.27 epoch(94_full 是 1.8)→ 数据
   还远没学完,官方配方用更大算力;我们的 2.267 只是"读了一遍的 27%"的成绩

## 11.2 剂量翻倍:10GB 主线档(2.01B token)

**目的**:11.1 证明了 mini 档(3.01 亿 token)能破冰(0 → ~4/20);
11.2 把剂量再翻 7 倍——官方 `pretrain_t2t.jsonl`(8.28GB)全量,同架构
同配方,看"首都题"这类 11-mm 与官方 SFT 都答错的题能不能首次答对。

### 两个工程事件(都是"换引擎"决策的产物)

1. **旧编码方案 OOM**:整库 `pool.map` 一次性回收 2.1B token 的 Python 列表
   ≈ 60GB+ → SIGKILL(137)。**流式分片版**(`prepare_corpus_chunked.py`):
   6 万行/窗,每窗立刻转 tensor 落盘分片,内存钉在窗口量级,支持断点续。
2. **只换引擎不换词表**(用户决策):词表保留我们重训的 26,566,执行换
   Rust(tokenizers)。`engine_swap.py` 把 bpe.json 在**内存**里直传给
   `models.BPE(vocab=我们的id映射, merges=元组对)`——元组绕开了
   tokenizer.json 空格分隔 merges 无法表达"含空格片段"的问题(如 `('.',' ')`)。

   **等价性验证(换引擎的守门员)**:300 行语料,python vs Rust **逐位一致
   0 不一致**,提速 **326×**——10GB 编码从 6-7 小时降到 **7 分钟**。
   代价:python 版已编的旧分片作废重切(引擎不同批混拼会污染数据);
   Rust 默认 decoder 会插空格,但我们管线用 python 侧解码(已验证一致),
   不受影响。

### 结果(126.6M 参数,词表 26,566,20000 步,11377s)

| | 11-mm(301M token, 词表 19,171) | **12-10g(2.01B token, 词表 26,566)** |
|---|---|---|
| 语料内 val(16-batch) | 2.267(ppl 9.7) | **2.067(ppl 7.9)** |
| 训练内 best val | — | 2.013(ckpt 存于 step 17000) |
| **ask 真实答对** | ~4/20 | **≈7/20**(命中 8 含 1 假阳) |
| fill 真实答对 | ~1/20 | ≈4/20 |

raw 格式行级(ask,首次连首都题都答对):

| 问题 | 12-10g 回答 |
|---|---|
| 中国的首都是哪里? | **"中国的首都是北京。"** ✓(11-mm 崩、官方 SFT 也错) |
| 中华人民共和国的首都是哪里? | "…首都是北京" ✓ |
| 故宫位于哪座城市? | "北京市中心…明清两代皇帝的宫殿建筑群" ✓ |
| 世界上最高的山峰是? | "珠穆朗玛峰…海拔8848米" ✓ |
| 大熊猫主要生活在中国哪个省份? | "四川省的山区" ✓(低频) |
| 水的化学式是什么? | "H2O" ✓(低频) |
| 圆周率的近似值是多少? | "3.14159" ✓(低频) |
| 秦始皇…第一个朝代? | 复读假阳(老毛病) |

### 结论

1. **剂量曲线闭环(本项目自证)**:150MB → 0/20;301M → ~4/20;
   **2.01B → ≈7/20**——剂量直接兑换检索能力,与 9.5 归因一致
2. **纯预训练(raw 格式)超过官方 SFT 64M 的 5/20(chat 格式)**:
   同 100M 级、无任何 SFT,把"数据缺口"补上后反超官方小模型——剩余差距
   确实只是剂量与工艺
3. 三个低频题(大熊猫/化学式/圆周率)同时答对,说明这不是关键词彩票,
   是知识分布成型了
4. 仍未解决:复读尾部、自问自答痕迹("答:…"是数据风格)、秦始皇类复读
   假阳。这些归 chat-SFT / 解码侧处理

诚实标注:11-mm 与 12-10g 词表不同(19,171 vs 26,566,分词器跟数据走),
跨词表 val loss 不可比——可比性挂在 20 题同裁判上;ask 命中 8 中 1 假阳
(秦始皇),真实 ≈7。

## 11.3 chat-SFT on 10GB 基座:与官方的终局并排

**目的**(数据线收官):把 10.3 的 chat-SFT 配方(官方 sft 数据渲染 → 去
think 噪音 → assistant 段掩码,800 步)搬到 12-10g 基座上,完成三件事:
① chat 格式与官方 64M 的同格式终局对比;② 复测 raw 格式(10.3 的诚实开口:
chat SFT 是否损伤 raw 能力);③ 顺带量 SFT 对语料内 val 的影响。

### 结果(12-chat-nt = 12-10g 基座 + 800 步 chat-SFT)

| 格式 | 命中 | 真阳审计 | 对比 |
|---|---|---|---|
| **chat** | 8/20(高 6 低 2) | **≈7 真**(1 假阳:秦始皇复读)+1 漏判(珠峰海拔答"8,848米",逗号未匹配)→ 内容正确 ≈8 | 官方 minimind-3 64M:**6/20(≈5 真)** |
| raw ask | 8/20(高 6 低 2) | ≈7 真(1 假阳:秦始皇) | 基座 12-10g:≈7 → **未损伤** |
| raw fill | 3/20 | ≈2 真 | 基座 ≈4 → 略降 |

语料内 val:2.067(基座)→ **2.200**(SFT 后,分布偏移预期内)。

### 终局并排(同格式、同裁判、同数据家族)

| | 我们 12-chat-nt | 官方 minimind-3 dense |
|---|---|---|
| 参数 | 126.6M(12 层/12q-6kv) | 63.9M(8 层/8q-4kv) |
| 预训练 | 官方 10GB 主线档,**20000 步 ≈ 0.08 epoch** | 官方 10GB,完整多轮训练 |
| SFT | 40k 行 × 800 步(去 think) | 全套 chat SFT |
| **chat 20 题(真阳)** | **≈7-8/20** | ≈5/20 |
| 吞吐 | 2.7 分钟/千步(单卡) | 多卡完整管线 |

**结论:数据家族同一份、我们只用了 0.08 epoch 与一小撮 SFT,就在官方模型
的原生格式上反超(≈7-8 vs ≈5)**。11.x 数据线至此闭环:剂量曲线
(0→4→7)、格式工艺(chat 壳学到)、与官方小模型的正面对比,全部有自家
受控实验背书。剩余差距只剩工程与生态(引擎/多卡/数据配套/serve)。

### 行为观察(诚实记录)

- **知识生成质量**:首答普遍正确且完整("珠穆朗玛峰(Mount Everest)…
  海拔8,848米(29,029英尺)"是全程最漂亮的一条),之后仍复读拖尾
- **"6,650公里"泄漏**:长江的长度数字出现在北京/省级行政区/俄罗斯等多条
  无关回答里——token 级吸引子,小模型的典型知识串扰
- failure 模式集中在"问法迁移"题(第几长河/哪一年/多少米)与"比较类"
  (最小/最大国家)——分布外问句仍脆弱,与 stage8 归因一一致

**chat11.py 使用笔记**(现场测试的结论,已写进脚本 docstring):
事实题用 `--temperature 0` 贪心(采样会幻觉:"水的化学式是 CO2O");
重复惩罚 1.2 会误伤知识召回(H2O/π 答丢),**1.1 是安全线**;复读拖尾是
本模型固有弱点(无 RLHF),惩罚只能缓解不能根治;多轮/长上下文会进入
位置外推区胡言(训练窗口 256),脚本按 512 token 预算自动截断历史。
