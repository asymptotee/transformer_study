# stage17_reason —— 能力边界扫描:126M 除了算术还能学会什么

**判别式问题**:stage16 证明了 126M 能用 14 分钟学会 5 位加法(0% → 83.5%)。
**但加法只是一个窄算法。**"处理输入 / 逻辑思维"能不能也这么教出来?

**答案:能,而且起点是 0。**

**关系推理和指令变换都在 14 分钟里从 0% 到 100%;状态追踪到 67%。**

**但(见第四节的泛化测试)那份 100% 的泛化半径很窄** —— 后面详述。

## 设计

### 三个任务

| 任务 | 例 | 难度阶梯 |
|---|---|---|
| **① 关系推理** | `A 比 C 高，D 比 B 高，B 比 A 高。谁最矮？C` | 3–6 个元素 |
| **② 指令变换** | `删掉 4 7 5 9 里的第 2 个。4 5 9` / `把 4 1 1 5 倒过来。5 1 1 4` | 串长 3–6 |
| **③ 状态追踪** | `盒子里有 1 5 个球。放进 9 个，放进 5 个。现在有几个？2 9` | 2–5 步 |

**三个都满足 stage16 那条铁律:程序生成 + 答案可验证 + 不需要 judge。**

### 防作弊设计(这决定了实验有效不有效)

**如果答案能靠位置猜,那 100% 就毫无意义:**

| 任务 | 防的是什么 |
|---|---|
| 关系推理 | 两两关系**打乱顺序**陈述;"问最大/问最小"**随机** —— 否则只要输出最后提到的那个就对了 |
| 指令变换 | 删除**位置随机**、数字随机 |
| 状态追踪 | 每步加减随机,保证中间结果不为负 |

### 配置

起点 `ckpt_11_5_final` · 每个任务**各训一个独立模型**(不混 —— 这样能分别回答
"这个维度能不能学会")· 5,000 步(60,000 条 ÷ batch 16 ≈ 1.3 epoch) ·
窗口 256 · **实测 14 分钟/组**

## 结果

### 起点(基座)—— 三个任务全是 0

| 任务 | 答对 | 空输出 |
|---|---|---|
| 关系推理 | **0/800** | 170/800 |
| 指令变换 | **0/800** | **800/800** |
| 状态追踪 | **0/800** | 0/800 |

**而"空输出"暴露了基座的三种性格:**

| 任务 | 空输出 | 行为 |
|---|---|---|
| 指令变换 | **800/800 全空** | 完全放弃,一个 token 不吐 |
| 关系推理 | 170/800,且**越难越多**(7→25→54→**84**) | 会试,但越难越早放弃 |
| 状态追踪 | 0/800 | 从不放弃,总是瞎答一个数 |

**它知道自己在哪些任务上不行。**

### 训练后

| 任务 | 起点 | **14 分钟后** |
|---|---|---|
| **关系推理** | 0/800 | **800/800 = 100%** |
| **指令变换** | 0/800 | **800/800 = 100%** |
| **状态追踪** | 0/800 | **536/800 = 67%** |

**状态追踪的曲线形状值得记**:2步 136 / 3步 146 / 4步 132 / 5步 122 ——
**几乎是平的**,不是"步骤多了就垮",而是**不随长度变化的固定 ~33% 错误率**。

**最可能的解释**:状态追踪是 **"追踪 + 算术"的复合任务**(要一边维护累加值、
一边做多位数加减),而 stage16 里单独的 2 位数加法也要 14 分钟专门训练才到 100%。
**复合引入了额外误差。**

## 泛化测试:**100% 的泛化半径很窄**

**为什么要做**:那 100% 是**同一个生成器、同一套措辞**测出来的。所以严格说只证明了
"学会了这个模板",不是"学会了推理"。**这个区分决定结论的方向。**

**设计**:只换**措辞**,答案形态**完全不变**(关系还是单个字母、变换还是逐位空格、
状态还是数字)。第一个 theme 是**训练同款**作对照。

### 关系推理 —— 词级替换能迁移,关系类型一变就崩

| 措辞 | 正确率 |
|---|---|
| 身高(**训练同款**,对照) | **200/200 = 100%** |
| 分数(新:`A 的分数比 B 高`) | **187/200 = 93.5%** |
| 年龄(新:`A 比 B 年长`) | **176/200 = 88%** |
| **排队(新:`A 排在 B 前面`)** | **47/200 = 23.5%** |

### 指令变换 —— 词换了还行,句式换了就完

| 措辞 | 正确率 |
|---|---|
| 倒序 / 删第k个(**训练同款**) | 200/200 = 100% |
| **逆序**(`逆序排列`) | **198/200 = 99%** |
| 去掉(`去掉…的第k个`) | 159/200 = 79.5% |
| 删去第k项(`删去第k项`) | **43/200 = 21.5%** |
| **反过来写**(`X 反过来写是什么？`) | **0/200 = 0%** |

### 状态追踪 —— 几乎完全不迁移

| 措辞 | 正确率 |
|---|---|
| 球盒(**训练同款**) | 121/200 = 60.5% |
| **苹果篮**(`增加/减少`、`有多少个`) | **9/200 = 4.5%** |
| **极简**(`初始…加…减…结果？`) | **5/200 = 2.5%** |

## 结论

### ① "处理输入"是可训练的,不是容量问题

| | 关系推理 | 指令变换 |
|---|---|---|
| **Holmes v1**(0.5B、4 倍参数、100 倍数据、专为推理设计) | **0/3** | **2/4** |
| **我们的 126M**(14 分钟训练) | **100%** | **100%** |

**同一个 126M,起点 0%,14 分钟后 100%。差别不在容量,在数据和格式。**

### ② 但"学会了推理"这个说法要打折 —— 泛化半径只有几个词宽

**两个都要说,不能只说一个:**
- ❌ 不是纯模板匹配:`高`→`年长` 保持 88%,`倒过来`→`逆序排列` 保持 99%
- ✅ 但也远不是"推理":句式一变就崩(反过来写 0%、苹果篮 4.5%、排队 23.5%)

**准确说法:它学会了「这个句式下的这个操作」。**

### ③ 复合任务更难

关系推理和指令变换都是**纯符号操作** → 100%。
状态追踪是**符号操作 + 算术** → 67%,而且错误率不随长度变化。
**说明瓶颈不在"追踪多少步",在复合本身。**

## 文件与复现

| 文件 | 内容 |
|---|---|
| `gen_reason.py` | 三个任务的生成器(含防作弊设计) |
| `eval_reason.py` | 逐档/逐 theme 评测(取**第一个**答案,防复读蒙对) |
| `gen_variant.py` | **泛化测试集**(换措辞,答案格式不变) |
| `supervisor12.sh` | 链:三个任务的起点评测 → 训练 → 评测 |
| `results/eval_*.json` | 逐题结果 |

```bash
PY=~/llm_study/.venv/bin/python; cd ~/llm_study/transformer_study/stage17_reason

$PY gen_variant.py                     # 泛化测试集
$PY ../stage14_multiturn/train_mt.py \
    --base-ckpt ../stage11_datascale/ckpt_11_5_final.pt \

    --eval-file relation_variant_eval.jsonl --label 17_relation_variant   # 泛化
```

## 下一步

**语料设计的第一原则确定了**(见 stage16 的格式混合实验):

> **同一种能力,必须用多种「语句结构」来教 —— 不只是换词,还要换句式、换标点、换表达框架。**

单一句式训出来的能力**泛化半径是零**;多种句式混训能撑到 84%,
**但仍过不了结构变化** —— 所以句式的多样性要比原来想的更激进。

**其余待办见 stage16 的"下一步"。**
