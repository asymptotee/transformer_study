# 阶段四：小模型为什么不连贯，以及怎么改善

## 要回答的问题

阶段三训出的鲁迅模型，**风格像鲁迅，但句子不通、逻辑破碎**：

```
我冒了严寒风的。我就是一个人，只能说，但我就要说，我还不再看不过这些……
```

为什么？怎么改善？本阶段用两个实验回答。

## 诊断：不是架构的错，是规模 + 分词

关键认知：**你的 Transformer 架构没有毛病。** 同一套架构放大几万倍就是能写连贯
文本的 GPT。所以不连贯不是设计缺陷，而是两个资源不够：

1. **参数太少**：只够记"字符层面的搭配统计"，装不下"语义关系"和"逻辑"。
2. **字符级太低效**：`逻`、`辑` 是两个无关 token，模型要从零学它们的关联；
   序列也太长，上下文窗口装的内容少。

一句话：**连贯 = 足够大的模型 × 足够多的数据 × 合适的分词粒度。**

---

## 实验 A：缩放实验（`scaling_experiment.py`）

**控制变量**：同一份鲁迅语料、同样 2000 步训练，**只变模型大小**。

| 规模 | 参数量 | 最佳 val_loss |
|---|---|---|
| small | 360,448 | 5.29 |
| medium | 983,936 | 4.84 |
| large | 2,067,072 | **4.53** |

**模型越大 → loss 越低**（曲线见 `scaling_curve.png`）。这就是 scaling law 的缩影：
给同样的数据，更大的模型能压缩出更多规律。

生成质量也随规模肉眼可见地改善（prompt = "我冒了严寒"）：

```
[small,  36万]  我冒了严寒在这时代，就是这里，还在在一个人……   ← 破碎
[medium, 98万]  我冒了严寒。这一天，不敢不过她的一个小……       ← 稍好
[large, 207万]  我冒了严寒儿的母亲。他说出，"你要不肯放去，
                你不肯说？"赵儿子说。                          ← 有对话结构了
```

large 已经能续出带对话结构的句子——**规模直接换来连贯性**。

## 实验 B：BPE 分词（`bpe.py` + `train_bpe.py`）

BPE 从字符出发，反复合并语料里最高频的相邻对，自动学出"子词"词表。
它学出的合并都是真实词语：**母亲、立刻、如此、因此、回到、故乡、人家**……

```
原文 19 字符: 我冒了严寒，回到相隔二千余里的故乡去。
BPE  15 token: [我, 冒, 了, 严, 寒, ，, 回到, 相, 隔, 二, 千, 余, 里的, 故乡, 去。]
```

### 公平对比：必须换算成"每字符 loss"

不同分词器的 loss 不能直接比（一个 token 含义不同）。换算成 **nats/char**
（`val_loss ÷ 每token含几字符`）才能比，它与分词方式无关：

| | 参数量 | val_loss/token | nats/char |
|---|---|---|---|
| 字符级 | 1,115,904 | 4.70 | **4.70** |
| BPE | 1,192,704 | 5.76 | 4.76 |

**意外的诚实结果：BPE 的 nats/char 反而略高（4.76 vs 4.70）**——在这个小规模、
同样训练预算下，BPE 在压缩效率上**没赢**。

### 但生成质量 BPE 更"顺"

```
[字符级] 我冒了严寒地面的脸上，他们要要说，是看不知道："老子"是"这么？"
         ← 字与字乱接

[BPE]   我冒了严寒，仿佛觉得有许多人便不愿意了许多许多，使我不懂得得很很很
         可的了，所以因为我是很可能知道我要求了，但是谁
         ← 有句式："仿佛觉得有…使我不懂得…"、"所以因为…但是…" 关联词、从句都在
```

BPE 输出语义仍不通，但**句法流畅得多**——它在"词块"层面操作，自然产出关联词、
从句这些词级结构。

### 为什么指标没赢、观感却赢了

1. **BPE 词表更大**（5192 vs 4592）→ 输出层更大、预测更难，2000 步没训透
2. **压缩红利在小规模显现不出来**：BPE 的真正优势是"同样窗口看到更多内容"
   （这里 64 窗口看 77 字符 vs 64）和"训练更高效"，要到**大规模、长上下文**才压过字符级
3. **词级 token 天然带来句法**：这是观感更好的原因，但不立刻反映在 loss 数字上

**结论：BPE 的价值是"规模化"的价值**——这正是真实 LLM 都用它的原因。

## 两个实验的共同教训

> **很多技术的意义要在规模中才兑现。**

- 缩放实验：规模直接降低 loss、提升连贯性（scaling law）。
- BPE：小规模 loss 未必更好，但它用更短序列、词级表示，**为规模化做好准备**。

这和本项目反复出现的主题一致（`CONCEPTS.md` 第四、五、六节）：**模型学到的是
它的参数能压缩的那部分规律**；规模越大，能压缩的越深（从字符搭配 → 词法 → 句法 →
语义）。小模型不连贯，不是错了，是**还没大到能压缩到语义那一层**。

真实 LLM 用几十亿参数 + 万亿 token + BPE，loss 一路压低，连贯性作为副产品**涌现**——
和这里 small→large 的趋势是同一条线，只是跨越了十几个数量级。

## 运行

```bash
cd stage4_scaling_bpe
PY=python

# 实验 A：缩放实验（约 15~20 分钟，训三个规模）
$PY -u scaling_experiment.py

# 实验 B：BPE（约 12 分钟，训 BPE + 字符级两个模型做公平对比）
$PY bpe.py            # 单独看 BPE 学出的合并和压缩率
$PY -u train_bpe.py   # BPE vs 字符级训练对比
```

两个实验都复用阶段三的 `GPT` 和鲁迅语料（`../stage3_gpt/luxun_clean.txt`）。
建议别同时跑，会抢 CPU。

## 文件

| 文件 | 内容 |
|---|---|
| `scaling_experiment.py` | 实验 A：训小/中/大三规模，画 loss-参数曲线，对比生成 |
| `bpe.py` | BPE 分词器（学合并 + encode/decode + 存取） |
| `train_bpe.py` | 实验 B：BPE vs 字符级，nats/char 公平对比 + 生成对比 |
| `scaling_curve.png` | 缩放曲线 |
| `bpe.json` | 学出的 BPE 合并规则 |

## 局限

- CPU 上的微缩演示，规模范围小（36 万~207 万参数），只展示**趋势**。
- BPE 在小规模没体现优势是**预期内**的——它的价值在规模化，本地到不了那个规模。
- 即便如此，方向是清楚的：要真正连贯，需要本地不可及的规模。你要的是搞懂机制，
  不是复现 GPT——这两个实验已经把"规模为什么重要、分词为什么重要"讲透了。
