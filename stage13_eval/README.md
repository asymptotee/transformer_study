# stage13_eval —— 13.1 评测扩容:131 题 + 修正判定 + 频率标定

**动机**(旧 20 题 harness 的四个问题,均已在历史实验里显形):
① 样本太小(2 题差=噪声);② "高频/低频"标签按旧 wiki 语料拍脑袋标的,
换语料后过期;③ 判定粗糙——关键词匹配双向翻车(复读假阳"秦始皇"、
逗号漏判"8,848米");④ 覆盖面偏(全是常识题,没覆盖语料主菜)。

## 设计

| 项 | 内容 |
|---|---|
| 题库 | **131 题 = 20 锚点(逐字保留旧题,保持与历史的连续性)+ 111 新题** |
| 分类 | 8 类:中国地理 20 / 世界地理 21 / 中国历史 17 / 科学 21 / 科技 15 / 生物自然 17 / 文化文学 10 / 生活常识 10 |
| 格式 | raw(问:…答:)与 chat(模板)双格式,贪心解码,**KV cache 增量**(快 ~10×) |
| 频率标定 | 对 10GB 语料全量扫描(847 万行,46 秒)统计每题标准答案出现次数,按**排名三等分**分档(high 43 / mid 44 / low 44;阈值 39,982 / 5,515) |
| 快照 | 原始频率计数保留在 `qa_v2_freq.jsonl`,阈值以后可重分档不重扫 |

**判定升级**(`eval_v2.py`,针对历史踩坑):
1. **归一化匹配**:去空白/半全角逗号顿号 → 修 "8,848米" 漏判
2. **复读假阳检测**:命中片段±2 字的上下文若整体出现在题干里,判为
   "题目回声"(suspect),不算真阳 → 修 "秦始皇…是秦始皇…" 式命中
3. 每题支持**多个可接受答案**(如"珠穆朗玛峰/珠峰"、"第一/最长")

**对账**(锚点子集 = 旧 20 题,新判定 vs 历史人工审计):11_2_10g raw
9/20(历史手审 ≈8,含 8848 漏判修复)、11_4_base raw 12/20(手审 ≈12)、
11_3/11_4_chat chat 8/20(手审 ≈7-8)——**自动判定已达到当年人工审计的
精度**。

## 关键发现

1. **剂量梯度第一次清晰可测**:raw 26 → 41 → 68(mini → 10GB 浅 → 10GB 深),
   131 题尺度下噪声 ~±4,三步全部显著——旧 20 题只有 ±2 噪声里的 4→7→12
2. **chat-SFT 的本质是"通道搬运"**:11_3_chat 把基座的 chat 从 2 拉到 40,
   代价是 raw 41→29;11_4_chat 把 chat 从 29 拉到 60,raw 68→61。
   **最终模型两通道持平(60/61)**——"chat 管道有损"的旧观察(20 题尺度上
   的 8 vs 11)在 131 题上不再成立:chat-SFT 充分后,知识能原样从 chat
   通道取出
3. **频率梯度**:11_4 系列 high/mid ≈ 57-65%,**low 仅 23-30%**——低频知识
   是当前前沿(与"记忆以高频共现为主"的历史画像一致)
4. **分类强弱**(11_4_base raw):文化文学 7/10、生物自然 11/17、科学 13/21
   强;中国历史 5/17、中国地理 7/20 弱——历史类答案多为低频实体
   ("溥仪"频次 14),地理类一半靠高频城市名

## 诚实的边界

- 题目由 AI 撰写,存在事实性笔误的可能;缓解:答案取通行事实、且**每个
  答案实体都经全语料频率扫描证实存在于训练语料**(freq 列可复查)
- 数字类答案的子串计数偏高(如"7"出现在任何含 7 的串里),其 freq 仅作
  相对排序参考,不作绝对判读
- 快照口径:评测用**贪心解码**、温度 0,可复现;换采样参数数字会变

## 13.2 可用性指标(自然收尾率 + 生成长度)

**动机**:131 题那套只看"第一句里有没有关键答案"(判分截断到第一个自问自答标记
之前),**完全不管后面写成什么样**。于是出现反直觉结果 —— chat 分最高的模型
可用性最差。

`eval_usability.py`:同题库、同 chat 模板、贪心,**预算给到 400 token**
(必须大于训练中位长度,否则测到的是"预算不够"而不是"停不住"),统计
**自然收尾率**(主动生成 `<|im_end|>`/EOS 而停止的比例)与生成长度。

| 模型 | 131 题 chat | **自然收尾率** | token 中位 | 字符中位 |
|---|---|---|---|---|
| 11_4_chat(旧基座,800 步) | 60 | **16.8%** | 400 | 524 |
| 11_5_final(基座,chat 壳) | 29 | 84.0% | **12** | 12 |
| 11_5_chat(800 步) | 78 | **18.3%** | 400 | 532 |
| 11_5_chat_2000(2000 步) | **83** | 45.0% | 400 | 514 |
| 11_5_chat_5000(5000 步) | 82 | 49.6% | 400 | 511 |
| **14_mt(多轮 SFT)** | 74 | **94.7%** | **31** | 36 |

**三条读法**:

1. **收尾率必须和准确率一起读**。基座那个 84% 是**假高** —— 中位只生成 12 token,
   不是"会停",是"没话说"(它 131 题只有 29 分)。一个什么都不说的模型收尾率
   必然 100%
2. **单轮 SFT 四档:16.8% → 18.3% → 45.0% → 49.6%**(含旧基座的 11_4_chat)。
   步数增加只略微改善,而且**全部卡在 50% 以下、token 中位数都打满预算** ——
   这是这一族模型的共同形态,不是某一档的偶然
3. **根因在数据**:单轮 SFT 语料的答案中位 **580 字符**(82% 超 300),多轮语料
   的目标轮中位只有 **110 字符**(16% 超 300)。单轮模型的字符中位 515 与 580
   吻合 —— **它就是在写被训练要写的长度,然后翻车**:126M 维持不了长文连贯,
   滑进复读,复读时永远不发收尾标记

**结论**:在这批模型上,**知识召回与可用性是反着的** —— 召回最高的(83)可用性
45%,召回 74 的可用性 94.7%。选型时两个指标都要看。

> ⚠️ 一个必须说明的公平性检查:14_mt 的短(中位 31 token)会不会是"过度简短"?
> 实测对开放式问题("写一段介绍长城的话")它写出约 180 字的完整段落,不敷衍。
> 短只出现在事实题上 —— 那本来就该短。**缩短来自数据形态(对话式回合),不是能力缺陷。**

## 13.3 用我们的尺子测 minimind 官方权重(2026-09-20)

**我们一直在跟自己比,从没跟参照实现比过。** 这一节把官方发布的 `.pth`
放进同一把尺子 —— 关键是**口径必须逐步对齐**:同 131 题、同 chat 模板、
同贪心、同 `max_new=80`;判分复用 `judge.py`(纯 python,所以在**跨词表**上也能用,
他们 BPE 6,400 / 我们 26,566,但判分在文本层做)。

脚本:`eval_knowledge_minimind.py` / `eval_usability_minimind.py` /
`eval_contamination_minimind.py`(模型换 `MiniMindForCausalLM`,其余口径照抄)。

### 知识(131 题 chat)

| 模型 | 真阳 | 说明 |
|---|---|---|
| **我们 `11_5_chat_2000`** | **83/131 = 63%** | 2,000 步 SFT |
| 我们 `14_mt` | 74 | |
| minimind `full_sft` | **44/131 = 34%** | **113,000 步 SFT** |
| minimind `grpo` | 46 | |
| minimind `ppo_actor` | **7** | ❌ **崩了**(见下) |

**他们多 56 倍的 SFT 步数(905,718 条 × 2 epochs ÷ batch 16),分数只有我们的一半。**

**排掉了两个 confound**:①词表粗 4 倍会让同样 `max_new` 下写得更少 → 给他们
3×/5× 预算,分数纹丝不动(43→44→44);②模型小一半(64M vs 126.6M)—— 规模解释不了。

**所以"SFT 数据量与步数"不是杠杆,那条 47 小时的对齐方案被数据否掉了。**

### 可用性(自然收尾率)—— 这一段最有价值

| 权重 | 收尾率 | token 中位 |
|---|---|---|
| `pretrain` | 100.0% ⚠️假高 | 324 |
| **`grpo`** | **90.1%** | 253 |
| **`ppo_actor`** | **84.0%** | 345 |
| **`full_sft`** | **52.7%** | 387 |
| `agent`(agentic RL) | 45.8% | 400 |

**结论一:SFT→RL 这一步值 30+ 个百分点。** 而且不是"答案变短"这个平凡解释 ——
PPO 中位 345 token(和 SFT 的 387 几乎一样),收尾率仍然 84%。**是真的学会了收尾。**

**结论二:他们的 SFT 也停不住(52.7%),和我们纯单轮的 45.0% 统计上分不开**
(n=131,±8.6%)。**说明"列表复读停不住"是这份 SFT 语料的常态,`14_mt` 的
94.7% 才是异常值** —— 它靠被窄化到只学对话式短回合换来收尾率。

**结论三:`ppo_actor` 知识崩了。** 131 题只有 7 分,输出退化成主题吸引子:

```
Q: 中国的首都是哪里？  → 中国的首都是"中国智慧城市建设"建设…
Q: 故宫位于哪座城市？  → ### 1. **技术与伦理** 随着科技的快速发展…   ← 答的是无关问题
```

**GRPO 没崩(44→46)。所以要做 RL,走 GRPO/CISPO,不要 PPO。**

**结论四:pretrain 的 100% 是假高** —— 和 13.2 里我们基座的 84% 同一个陷阱,
基座在 chat 壳下"会停"是因为行为完全不同,不是因为会收尾。

### 多轮(污染测试)

| 模型 | 多轮占比 | 单轮 | 多轮 | **污染率** |
|---|---|---|---|---|
| 我们 `11_5_chat_2000` | 0% | 83 | 34 | **63.9%** |
| minimind `full_sft` | 22.2% | 52 | 31 | **53.8%** |
| 我们 `14_mt` | 100% | 74 | 72 | **8.1%** |

**非线性:22% 多轮只把污染率从 63.9% 挪到 53.8%,而纯多轮是 8.1%。**
这条直接否掉了"按自然比例混训"的配方(见 `stage14_multiturn/README.md` 14.5)。

> ⚠️ 跨模型比时注意:他们跑在 `rep_penalty=1.1`,我们自己那两次是纯贪心(等同 1.0)。
> 各自的**污染率**是内部一致量(同模型同参数),但跨模型比较是近似的。

## 判分修正 #2(2026-09-15,11.5 审计发现)

背景:11.5 终态比 130k 多 5 个真阳,逐条审计时发现 2 个是**判分假阳** ——
模型首答是错的,答案词只出现在它随后的"自问自答"里:

```
中国最长的城墙是？ → 首答"秦始皇陵"(错)
   '…是秦始皇陵。\n问：长城的长度是多少？\n答：长城的长度是21,196公里。'  ← "长城" 命中回声
中国的第一大城市是？ → 首答"北京"(错)
   '…是北京。\n问：…\n答：…是上海。'                                      ← "上海" 只在回声里
```

修正:**匹配区间截断到第一个自问自答标记之前**(`问：/问题：/Q:/<|im_start|>`…;见
`judge.py:answer_span`)。chat 格式同源:模型复读 `<|im_start|>assistant` 模板时,
答案词也只出现在复读里。

**为什么不选"只看首句"**:首句规则会误伤真答案 —— 重力加速度(先铺垫
`F=ma`,下一句才说 9.8)、李白(首句生平,后文才"被誉为诗仙")、《红楼梦》
(后文才"作者是清代作家曹雪芹")。实测首句规则在 12 次评估里掉 15 个,审计后
**8 个是误伤**;回声截只掉 3 个,审计后**全是硬假阳**。

**离线复算结果**(`rejudge.py`,不需 GPU):

| run | raw | chat |
|---|---|---|
| 11_1 / 11_2 / 11_3 / 11_4_base / 11_4_chat | **全部不变** | **全部不变** |
| 11_5_base | 71 → 70 | 20 → 19 |
| 11_5_final | 76 → 74 | 29 → 29 |

历史 5 个 run 一个都没变 → 上面的剂量曲线(26→41→68)不受影响,只 11.5 两条需改。

**已知残留(未修)**:答案词只出现在"**无标记的后续罗列**"里仍记真阳 —— 如问
"蝴蝶是由什么变成的",首答"由细胞和组织组成"(错),后文罗列生命周期
"卵、幼虫、蛹和成虫"里冒出"幼虫"。量级:11_5_final/raw 的 74 个真阳里约 3 个
属此类。要修需引入"首答已给出不同答案则后续不算"的语义判断,收益小、误伤风险大。
